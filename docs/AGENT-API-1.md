# AGENT-API-1: the farm as something an agent can drive, and the guide that ties it to the Tiiny

Jason, 2026-09-14 10:09 CDT: "since we've got our API where your agent can do stuff off of your
personal API, we should have something like a farm API. It would give you a breakdown and help
the AI agent as well as the end user learn how to use this in conjunction with the API."

Today: docs/agents.txt is served as /docs/agents/ and /llms.txt, the Worker has a JSON API
(catalog.json, /manifests/<id>.json, /api/seeds, /api/media, /api/seeds/<id>/art,
/api/seeds/<id>/release-check, tokens, owners), and the CLI prints prose. There is no
machine-readable CLI output and no single document that describes every route.

## Build

1. **`--json` on the CLI**: `farm list --json`, `farm status --json`, `farm check --json`,
   `farm doctor --json`, `farm install <id> --json -y`, `farm start <id> --json`, `farm stop
   <id> --json`. One JSON object on stdout, nothing else on stdout, prose to stderr, exit codes
   unchanged. Shapes documented in the guide and pinned by tests. Errors are `{"error": {...}}`
   with the same sentence the person would see.
2. **OpenAPI 3.1 at /docs/openapi.json**, generated by scripts/build-site.py from a single
   source in the repo (a YAML or Python description next to the Worker, kept in step by a test
   that walks the Worker's route table and fails on any route missing from the spec or any spec
   path with no route). Every route, method, auth (session cookie, `farm_` bearer token,
   nothing), request and response shapes, error shapes, rate limits. Served with the right
   content type and linked from /docs/api/.
3. **The agent guide**: docs/site/11-agents.md, replacing the text page at /docs/agents/ (keep
   the URL; /llms.txt stays a plain-text index that points at it and at /docs/openapi.json).
   Sections, each with a curl and a Python (standard library) example: find the person's Tiiny
   (discovery on port 39218, the USB /30, the LAN sweep the apps use); put its key where the
   farm reads it (`farm device --key-stdin`, never on a command line); read the catalog and a
   manifest; install, start, stop, check and update an app for a person with `--json`; run
   `farm doctor --json` and act on each finding; publish and update a listing with a `farm_`
   token; ask the farm to draw art; and how the farm composes with the device's own
   OpenAI-compatible API (the apps call http://<tiiny>/v1 with the same key; AINode Pocket
   fronts a fleet at one endpoint). Plain words, Jason's voice, no em dashes, Tiiny.
4. **Titanium Bot reads it**: nothing to build here, note in the report which URL Titan's
   web tool should fetch first (/llms.txt), so the next Titanium Bot skill can be one line.
